# Experimental results and evidence provenance

**Observed on local test workstation on 19 November 2026**. Environment: Ubuntu 24.04.5 LTS, RTX 5080, Ollama 0.17.6, `qwen3:4b` on GPU. **The original operator-generated reports are included in [`evidence/`](../evidence/README.md), with SHA-256 checksums matching the source files on local test workstation.** These are controlled-lab records, not independent production measurements.

## F01 — Tenant isolation

`python3 -m llm_failure_lab.live_f01 --report reports/f01-live.json`

- One real Ollama structured tool proposal targeting `tenant_alpha` / `payments-api` / `staging`.
- Alice (authorized): both paths reported status 200 and one synthetic read.
- Bob (`tenant_beta`): baseline reported status 200 and one synthetic read of Alice's record; guarded reported 403 `ACCESS_DENIED` and **zero** synthetic reads.
- Reported acceptance: `f01_acceptance_passed=true`.

## F02 — Synthetic async tool timeout

`python3 -m llm_failure_lab.live_f02 --report reports/f02-live.json`

- Injected slow tool: 300 ms; guarded timeout configured at 80 ms.
- Baseline reported ~300.495 ms, result status 200, `verification=verified`.
- Guarded reported ~80.291 ms, result status 504, `verification=unverified`, no returned deployment and one cooperative cancellation.
- Model tool proposal was real, but the delayed tool was local and synthetic; the reported elapsed times exclude model generation.
- Reported acceptance: `f02_acceptance_passed=true`.

## F03 — Retry policy

`python3 -m llm_failure_lab.live_f03 --report reports/f03-live.json`

- After three synthetic 503 responses: baseline recovered on 4th attempt; guarded stopped after 2 attempts with `RETRY_BUDGET_EXHAUSTED` and unverified result.
- After a synthetic 403: baseline retried; guarded rejected retry immediately.
- After a synthetic 429 with 300 ms `Retry-After`: guarded stopped because delay exceeded a **150 ms tool-operation** deadline.
- No real 429/503 was generated by Ollama; this does not establish the optimal retry policy under load.
- Reported acceptance: `f03_acceptance_passed=true`.

## F04 — Tool call quota

`python3 -m llm_failure_lab.live_f04_f05 --report reports/f04-f05-live.json`

- One **real** LLM tool proposal, replayed **three times synthetically**.
- Baseline: 3 dispatched invocations, 3 reads, 0 budget rejections.
- Guarded: 1 dispatched invocation, 1 read, 2 budget rejections (`TOOL_CALL_BUDGET_EXCEEDED`).
- No autonomous multi-step agent loop or token budgeting was tested.
- Reported acceptance: `f04_acceptance_passed=true`.

## F05 — Tool evidence gate

Same command/report as F04, with synthetic fixture responses.

- Complete: both accepted as verified.
- Missing `reason`: baseline verified; guarded 502 `INCOMPLETE_TOOL_EVIDENCE` with no deployment.
- Mismatched `service`: baseline verified; guarded 502 `TOOL_RESPONSE_MISMATCH`.
- Invalid `status`: baseline verified; guarded 502 `INVALID_DEPLOYMENT_STATUS`.
- No generated final model answer or provenance verification was tested.
- Reported acceptance: `f05_acceptance_passed=true`.

## Important interpretation constraints

1. `http_status` is a **local result field**, not an actual HTTP response.
2. LLM chooses **one** structured tool call per live runner; subsequent F04 submissions are locally synthesized.
3. Dataset, dependency faults and identities are educational **fixtures**; do not infer production threat resistance.
4. Tests exercise specific design invariants; they do not prove prompt-injection resistance, LLM truthfulness, confidentiality across a real network, compliance, GPU cost management or observability completeness.
5. A clean GitHub release should include the **actual operator-generated reports** (after review) or a cryptographically identified evidence archive from local test workstation. Do not backfill missing raw reports from these narrative summaries.
